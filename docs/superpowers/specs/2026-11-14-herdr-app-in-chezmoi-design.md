# Herdr app config under chezmoi

**Status:** Implemented (branch `chore/herdr-app-in-chezmoi`, its PR against `main`; plan
`docs/superpowers/plans/2026-11-15-herdr-app-in-chezmoi.md`)
**Date:** 2026-11-14
**Branch:** `chore/herdr-app-in-chezmoi`
**Sign-off:** Michael, 2026-11-15; Codex spec review approved (round 2).

Michael has decided to move from the herdr TUI to the Herdr desktop app (cask `herdr-app`,
0.1.x). His working app setup lives in `~/.config/herdr-app`, outside chezmoi and outside any git
repository. This line puts the files he authored there under chezmoi, so they are versioned and
a new machine gets them, and adds the cask to the Brewfile. The app must behave exactly as it
does today.

A parallel line, `feat/herdr-app-native-tools`, makes xreview and wt app-native. It moves
`xreview-shim/` into the dotfiles and shrinks `xreview-app`, `wt-app` and `claude-app` to thin
wrappers. Those three wrappers, and `claude-settings.json`, stay until the TUI is retired. This
line merges first, and the parallel line rebases onto it.

## Goals

- Michael's authored app config is in `dot_config/herdr-app/`.
- `command chezmoi --source <checkout> diff ~/.config/herdr-app` prints nothing. So the first
  `chezmoi apply` after merge writes nothing under `~/.config/herdr-app`: no mod reloads, and no
  runtime file is touched.
- Runtime state, files the app ships or rewrites, and the generated clones can never reach the
  public repository by accident.
- A new machine can rebuild the setup, using one documented manual step.
- The app's two test suites move into the repository's `tests/` and run against the source.
- `cask "herdr-app"` is in the Brewfile.

## Non-goals and anti-goals

- No change to how the app behaves, to any authored file's content (the only change is a home
  path written as a template that renders to the same bytes), or to the respaces guard.
- The herdr TUI keeps working: nothing under `dot_config/herdr/`, the TUI scripts, plugins or
  hooks changes, and `brew "herdr"` stays.
- Not in this line: xreview, wt, the agent instructions (`.chezmoitemplates/agents/`) and the
  Claude Code settings (`dot_claude/`). They belong to the parallel line.
- No live file under `~/.config/herdr-app` changes before the PR merges. Michael has live
  sessions in the app.
- Anti-goal: a chezmoi apply that resets something the app wrote, or a commit of app state or
  of Herdr's shipped code.

## Approaches

Decided with Michael on 2026-11-14 (all three as recommended).

1. **Test suites: repo `tests/`** (chosen) or kept in the app tree and deployed. The repo rule
   is that suites live in `tests/`, never land in `$HOME`, and run through `run.sh` with
   `--changed`. Kept in the app tree, they would deploy to `~/.config/herdr-app/tests`, and
   `run.sh` would never run them.
2. **`settings.json`: seed only** (chosen) or fully managed. The app writes this file. Fully
   managed, every zoom press would show as drift, and the next apply would ask to overwrite it
   (or reset it). A seed (`create_`) gives a new machine the settings, and chezmoi never
   touches the file again. The cost is that a later change is versioned only if brought into
   the source by hand.
3. **New-machine clones: a manual step** (chosen) or automated in `configure.sh`. The brief
   proposed letting a missing clone trigger respaces through `mods/respaces-guard`. That can't
   work. The app won't show a layout whose mods are missing: the binary has "needs mods that
   aren't here … Showing Herdr instead. Missing: …". `respaces-guard` lives in the `michael`
   layout, so on a new machine it never runs, and a missing-clone check inside it would never
   run either. Automating this in `configure.sh` would need it to start a GUI app during setup.
   For two machines, one documented step is proportionate.

## Design

### The managed tree

`dot_config/herdr-app/` holds the authored files, unchanged and under their own names:

- `bin/executable_<name>` for each of the 10 scripts, and
  `xreview-shim/executable_herdr` (mode 755 today).
- `patches/phases.js`, `patches/worktree-actions.js`.
- `mods/<nav|resume|usage|respaces-guard>/main.js` and `mod.json`.
- `layouts/michael.json`, `themes/tokyo-night.json`.
- `keys.json.tmpl`, `programs.json.tmpl`, `claude-settings.json.tmpl`: each `/Users/michael`
  becomes `{{ .chezmoi.homeDir }}` (as the LaunchAgent templates already do). They render
  byte-identical to the live files. Note: `keys.json` has no trailing newline, and the render
  must not add one.
- `create_settings.json`: the seed.

Nothing else from the tree is in the source. chezmoi leaves unmanaged files in a managed
directory alone, so runtime files, shipped files and the clones stay untouched. No `exact_`
prefix is used anywhere.

### The ignore allowlist

`.chezmoiignore` gets an allowlist for `.config/herdr-app`, built like the `~/.claude` and
`~/.codex` ones: ignore the directory's contents, re-include each authored file or directory one
level at a time, then ignore the app-written `mods/*/gpui-kit.d.ts` and `mods/*/jsconfig.json`.
Directories that hold only Michael's files (`bin`, `patches`, `xreview-shim`) are re-included
whole. `layouts`, `themes` and `mods` are re-included only for the named entries, so that
`chezmoi add ~/.config/herdr-app` (or of any runtime file) adds nothing it shouldn't. The
`tests` directory is not re-included, because the suites move to the repo.

The cost is the same as for the existing allowlists: a new authored file outside the whole
directories (a new mod, layout or theme) needs its own `!` entry, or it silently never deploys.
The AGENTS.md rule that names the allowlisted trees adds `~/.config/herdr-app`.

### The suites

`tests/run.zsh` becomes `tests/herdr-app.test.sh`, and `tests/xreview-app.zsh` becomes
`tests/herdr-app-xreview.test.sh` (both zsh, mode 755). Their stubs and fixture move to
`tests/fixtures/herdr-app/`. Their assertions stay the same. Only what's needed to fit the repo
changes:

- They test `dot_config/herdr-app` rendered as chezmoi would deploy it (names without
  `executable_`, modes, templates), in a scratch directory, never the deployed tree. A wrong
  prefix or mode then fails a case. The render runs with a scratch home as chezmoi's home
  directory, into `<scratch home>/.config/herdr-app`. The templated JSON then names the scratch
  tree, which is what `claude-app`'s checks compare against: it derives its paths from `$0`.
  Acceptance 2 is the separate render against the real home.
- `patch-mod`'s ten checks against Herdr's shipped `menu` and `spaces` mods ("applies to the
  shipped mod", "changed it", and the missing and duplicated anchor cases) read those two
  `main.js` files from the installed app, `${HERDR_APP_HOME:-$HOME/.config/herdr-app}/mods/`.
  Herdr's code is never copied into the repo. When the files are absent (no app on this
  machine), those checks print one `SKIP` line and do not run, like the Ctrl+C cases without a
  pty. When present, they assert as today. So an app update that moves a line `patch-mod`
  matches fails them on every branch until `bin/patch-mod` is brought up to date. That is the
  same moment the guard's start-up toast reports it.
- `herdr-app.test.sh` links the source `dot_config/zsh` into its scratch HOME in place of the
  deployed `~/.config/zsh` (the names there carry no prefix). The `wt` functions it calls are
  then the ones being merged.
- Each passing check prints `  PASS: <description>`, so `run.sh` counts it. Each suite still
  exits nonzero on any failure.
- Each suite exits 2 when its subject is missing. `tests/missing-subject.test.sh` gets a row
  per suite.
- Every file a suite loads gets its row in `.scripts/test-audit/subjects.tsv`, and the existing
  `dot_config/zsh/functions` row adds the new suite to its `loaded_by`.

Both suites pass sandboxed today. The two Ctrl+C cases need a pty and print `SKIP` without one,
as they do now (the sandbox can read the installed app's mods). So neither suite carries a `test-requires` tag, and both run in every
`./tests/run.sh`. After the merge, the live `~/.config/herdr-app/tests` is unmanaged and
unused. The final report gives Michael the command to delete it.

### Brewfile

`cask "herdr-app"` goes in the unconditional cask block of `dot_config/homebrew/Brewfile.tmpl`,
in alphabetical order, with a short comment in the file's style. It installs on both machines,
as `brew "herdr"` does. The cask is in homebrew/cask, so no new tap is needed.

### A new machine

Provisioning installs the cask and deploys the files, but not the two clones. Two places get
one step each: README's manual new-machine list and `provision.sh`'s "Next steps". The step:
open Herdr once, run `~/.config/herdr-app/bin/respaces` with its window open, then pick the
`michael` layout (cmd-shift-L). On its first run the guard finds no recorded version, records
the one respaces just built on, and handles later updates as it does today.

### Documentation

One AGENTS.md Rules bullet for `~/.config/herdr-app`. It says that only Michael's files are
managed (the allowlist), that `settings.json` is a seed because the app writes it, that the
`michael-*` mods are generated by `bin/respaces` and are never added, and that the suites are
`tests/herdr-app*.test.sh`. It also says that `herdr-app`'s `patch-mod` checks read the
installed app's shipped mods: they skip without the app, and fail after an app update moves a
patched line. The allowlist sentence names the tree. The Layout block's
`dot_config/` line needs no change.

## Acceptance

1. `command chezmoi --source <checkout> managed --path-style relative ~/.config/herdr-app` lists
   exactly the managed tree above.
2. `command chezmoi --source <checkout> diff ~/.config/herdr-app` prints nothing, and
   `… status ~/.config/herdr-app` prints nothing. Neither looks at a `create_` file whose
   target exists, so `dot_config/herdr-app/create_settings.json` is also compared byte for
   byte with the live `settings.json` (`cmp`).
3. In a scratch copy of the source, `chezmoi add` of `~/.config/herdr-app` as a whole, of
   `view.json`, `shared.json`, `data/`, `layouts/.state/` and `mods/michael-spaces`, and of a
   shipped mod, adds nothing. This is checked in a suite that already tests allowlists (extend
   it rather than add a new one).
4. `command chezmoi --source <checkout> cat ~/.config/homebrew/Brewfile` differs from main's
   render by the one cask line.
5. Both moved suites pass from the repo with the app installed: `herdr-app` 139/139 with 2
   skipped sandboxed (141/141 unsandboxed), and `herdr-app-xreview` 262/262. These are the
   live-tree baselines measured on 2026-11-14. Hiding the installed shipped mods skips exactly
   the ten `patch-mod` checks.
6. `./tests/run.sh --changed` is green on the final commit.
7. No file under `~/.config/herdr-app` or `~/.config/herdr` was modified by this line.
8. Just before the PR is opened, and again before the final report, every managed file is
   compared with its live counterpart: acceptance 2, including the seed's `cmp`. The live tree is the truth until merge.
   If Michael's in-app sessions edited a file after it was copied, the live version is brought
   into the source, the suites run again, and the report names the file.

## Left to the builder

- How the suites render the tree (for example `chezmoi archive` of the two subtrees, externals
  excluded, unpacked into the scratch root), as long as it renders as chezmoi would deploy.
- The exact `.chezmoiignore` lines and the suite that carries acceptance 3.
- Commit split, as long as each commit leaves the suites green.

## After merge (Michael)

- `chezmoi diff ~/.config/herdr-app` first: it must print nothing. Any line means a live edit
  landed after the PR's last check; bring it into the source before applying. Then
  `chezmoi apply` changes nothing under `~/.config/herdr-app`. `brew bundle install` finds the
  cask already installed.
- `rm -r ~/.config/herdr-app/tests`: the suites now live in the repo.
- From then on, app config changes go through a `wt` checkout of the dotfiles. To bring a live
  edit back, use `command chezmoi --source <checkout> add <file>`. A file the allowlist doesn't
  cover needs its `!` entry first.
- The `herdr-app-trial` memory says the app config is unmanaged and that nothing for it goes
  in git. Both stop being true at merge.
