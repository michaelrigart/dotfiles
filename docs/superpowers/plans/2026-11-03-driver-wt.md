# Driver-run wt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** In progress on `driver-wt` (plan review; the dotfiles have no MR)

**Goal:** The driver may open a `wt` checkout for each independent line of work in a `~/Code`
repository. It runs `wt --no-focus`, unsandboxed and through the classifier, and reviews each line
with `xreview -C <checkout>` in that checkout's own Codex pane. The apply window follows the edited
file's checkout. Teardown stays Michael's.

**Architecture:** One settings line and its pins. A global `-C` option in xreview that enters the
checkout before any subcommand runs. An apply guard keyed by the git toplevel of the edited file.
A `--no-focus` flag threaded `wt` → `dev` → `layout.sh`, where one helper does every focus. Then
Michael applies the branch, a driver session checks it live, and only then does the instruction text
change.

**Tech Stack:** bash (xreview, the guards, the suites), zsh (`dot_config/zsh/functions`,
`layout.sh`, the `dev` and `wt-functions` suites), jq, the chezmoi `modify_` script, Python 3
(`measure-interventions`), herdr 0.9.x, Claude Code sandbox `excludedCommands`.

**Spec:** `docs/superpowers/specs/2026-11-03-driver-wt-design.md` (Approved, signed off 2026-11-03;
Codex xr-1793746694-a058d9a7). Read it whole first. Its rulings are settled, and this plan changes
none of them.

## Global Constraints

- **Scope.** Edit only the plan worktree's source. `chezmoi apply` is Michael's. Never run `wt`,
  `wt-rm`, `dev` or `layout.sh` for real, and never run xreview against the real Codex pane: the
  suites stub them. Task 8 is the one exception, and Michael starts it.
- **Before Task 1,** the controller sets the spec's Status to `In progress`.
- **Commits.** Only the controller commits. An implementer runs its focused tests and hands back
  uncommitted. Imperative mood, no agent attribution. Before each commit, check that
  `git branch --show-current` prints `driver-wt`, then read `git diff --cached`.
- **Batches.** The controller commits and reviews each task on its own commit. After each batch it
  runs `./tests/run.sh`, plus each heavy suite whose tagged files the batch changed, by exact name:
  `./tests/run.sh xreview` after Batch A, `./tests/run.sh wt-functions` after Batch B.
- **Running suites.** Execute them; never prefix an interpreter. `dev` and `wt-functions` are zsh
  suites, and under `bash` they report bogus syntax errors. An exact name lifts a `# test-requires:`
  gate. `run.sh` holds one machine lock, so a parallel implementer runs `./tests/<name>.test.sh`
  directly.
- **The heavy xreview suite runs once per batch, not per task.** Task 2's red and green runs use a
  cut of it instead: the setup (every line before `echo "A. rounds are not capped`), then Task 2's
  new section `CK.` and the summary lines after it, with the `SRC=` line pointed at the worktree.
  `awk` and `sed -n` build it into `$TMPDIR`, and `bash` runs the cut. The new section therefore
  defines its own helpers and does not use Q's `hstate`.
- **Pre-existing failures.** A failure counts as pre-existing only if the same suite fails on a clean
  checkout of main's tip.
- **The settings jq program** is one single-quoted shell string. Its comments hold no apostrophe and
  no backslash (`dot_claude/modify_private_settings.json:43`).
- **Line caps** (Task 9): `global.md` at most 150 lines and 100 columns, `claude-code.md` at most 50
  lines. Both are at their caps, so Task 9 is net zero in each.
- **No new prompts.** Add no allow rule and no `ask` rule.
- **House style in zsh:** `emulate -L zsh`, `builtin cd`, and `_wt_git`/`hl_git` for git, as the
  files already do.

### Task 2: `xreview -C <checkout>`

**Depends on:** none. **Tier:** sp-standard. **Spec:** §2.

**Interfaces:**
- **Where it is parsed.** `-C <dir>` is accepted only as the first argument. It is parsed after the
  help loop (`:1973`) and before the dispatch `case`. On success it enters `<dir>`, so every later
  lookup resolves there.
- **Refusals,** on stderr with exit 1, before anything is touched:
  - `xreview: -C needs a checkout directory`
  - `xreview: cannot enter <dir>`
  - `xreview: <dir> is not inside a git checkout`
- **Usage.** The first line becomes `usage: xreview [-C <checkout>] <command> [args]`. A new line
  starts `  -C <checkout>` and says that the command runs as if started there, with relative paths
  resolving there. The `*)` arm's usage message gains `[-C <checkout>]`.
- **`nonce_elsewhere <nonce>`** prints the state directory of the first other checkout that holds
  `turns/<nonce>`, searching `${XDG_STATE_HOME:-$HOME/.local/state}/xreview/*/turns/<nonce>`. It
  returns 1 when there is none.
- **collect.** When this checkout has no turn record for the nonce and `nonce_elsewhere` finds one,
  collect refuses with
  `xreview: <nonce> was dispatched from another checkout (its state is <dir>); run collect with the -C it was dispatched with`.
  Otherwise it gives today's "ambiguous" refusal.
- **apply `<nonce>`.** It first runs `assert_id` on the nonce, so a crafted nonce cannot widen the
  search. With no turn record here and one found elsewhere, it refuses with the same message, saying
  `apply` instead of `collect`, and writes no marker. A nonce on record here, or nowhere, opens the
  window as today. `apply --done` is unchanged.
