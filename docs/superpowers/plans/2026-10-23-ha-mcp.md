# Home Assistant MCP Implementation Plan

**Status:** Approved

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Declare the Home Assistant MCP server (ha-mcp) for Claude Code and Claude Desktop in the dotfiles, with the token rendered from 1Password into one file that sandboxed Claude sessions cannot read.

**Architecture:** A chezmoi template renders `~/.config/ha-mcp/env`; a POSIX launcher `~/.local/bin/ha-mcp` loads it and runs `uvx ha-mcp@latest` on mise's global Python. Claude Desktop points at the launcher through a `modify_` script; Claude Code through a new `claude_mcp` kind in `reconcile-agents.sh`. The settings script denies the env file in both credential layers.

**Tech Stack:** POSIX sh (launcher), bash 3.2-compatible (`/bin/bash`) for the modify script and reconciler, jq, chezmoi templates, mise, uv.

**Spec:** `docs/superpowers/specs/2026-10-23-ha-mcp-design.md` (Approved).

## Global Constraints

- No secret in the repo. The only token source is `onepasswordRead "op://Private/Home Assistant MCP/credential"`; the URL is `onepasswordRead "op://Private/Home Assistant MCP/hostname"`.
- No script, test or log line ever prints the token or an existing MCP entry's `env`. Tests use the sentinel `SECRET-TOKEN-123` and assert it is absent from every output.
- Launcher path is `$HOME/.local/bin/ha-mcp` everywhere; env file is `$HOME/.config/ha-mcp/env`.
- Server names stay `ha-mcp` (Claude Code) and `Home Assistant` (Claude Desktop).
- The launcher runs exactly `mise exec -- uvx --python <mise which python> ha-mcp@latest` from `$HOME`. No version pin, no `--refresh`, no offline fallback.
- Bash scripts run under `/bin/bash` 3.2: no associative arrays, `mapfile`, `${x,,}`.
- Every suite is `tests/<subject>.test.sh`, mode 755 (`git add --chmod=+x`), executed directly (`./tests/x.test.sh`), never through an interpreter. A suite whose subject is missing exits 2. Output idiom `  PASS: …` / `  FAIL: …`. Report results as passed/total.
- Never start a Bash call with `cd`; use absolute paths or `git -C`.
- Implementers do not commit. They run only their task's suite and report back; the controller commits each task on its own.
- `chezmoi apply` is Michael's. Previews only: `command chezmoi --source <checkout> cat|managed …`.

## Review Focus

1. A Desktop config whose stale `Home Assistant` entry carries the token, beside other servers and preferences: output keeps everything else and contains no token (Task 3, "stale entry replaced, token gone").
2. Reconciling a stale `ha-mcp` entry with the token in `env`: the old entry is replaced and the token never reaches stdout, stderr or the CLI call log (Task 4, "stale entry: replaced, token never printed").
3. The server starting in a project directory: the launcher still resolves mise from `$HOME` (Task 1, "runs from HOME, not the caller's directory").
4. A fresh machine: no `~/.claude.json` yet, no Desktop config yet. Reconcile adds; the modify script emits the entry alone (Task 4 "no ~/.claude.json", Task 3 "empty input").
5. A token or URL with shell metacharacters: the rendered env file sources back to the literal value (Task 1, "rendered values source back literally").

### Task 4: `claude_mcp` in the reconciler

**Depends on:** none

**Files:**
- Modify: `.scripts/reconcile-agents.sh` (header comment; `parse_manifest`; new `reconcile_claude_mcp`, called at the end of `reconcile_claude`)
- Modify: `dot_config/agents/plugins.conf` (Kinds comment; the declaration)
- Test: `tests/reconcile-agents.test.sh` (claude stub; `run`; a new section before the live section)

**Interfaces:**
- Consumes: the launcher naming rule, `$HOME/.local/bin/<name>` (Task 1 creates `ha-mcp`).
- Produces: manifest line `claude_mcp  <name>`; list `claude_mcps`.

- [ ] **Step 1: Extend the test.** The claude stub gains `"mcp "*) echo "$*" >> "$CALLS"; exit "${MOCK_CL_MCP_RC:-0}" ;;` before `*)`. `run` passes `HOME="$CFG"`; `reset_mocks` deletes `$CFG/.claude.json` and `$CFG/.local`. With `L="$CFG/.local/bin/ha-mcp"` and `J='{"type":"stdio","command":"<L>","args":[],"env":{}}'`, cases (manifest `claude_mcp ha-mcp`):
  - "no ~/.claude.json": calls contain `mcp add-json ha-mcp <J> --scope user`; no `mcp remove`; exit 0.
  - "absent from mcpServers" (file `{"mcpServers":{"other":{"command":"x"}}}`): add-json called; `other` never named in any call.
  - "matching entry": file holds `J` under `ha-mcp` → no `mcp` call; output has `claude mcp present: ha-mcp`.
  - "stale entry: replaced, token never printed": file holds `{"type":"stdio","command":"uvx","args":["ha-mcp"],"env":{"HOMEASSISTANT_TOKEN":"SECRET-TOKEN-123"}}` → calls are `mcp remove ha-mcp --scope user` then `mcp add-json ha-mcp <J> --scope user`, in that order; `SECRET-TOKEN-123` absent from output and from `$CALLS`.
  - "remove fails": stale entry, `MOCK_CL_MCP_RC=1` → no add-json call; exit 1.
  - "invalid ~/.claude.json": file `not json` → no `mcp` call; warning names the file; exit 1.
  - "bad name": `claude_mcp ../x` → warned and skipped, no `mcp` call; exit 1.
  - "launcher missing": output warns `launcher not found: <L>`; registration still called. With `<L>` created executable, no such warning.
  - Every scenario in the existing sections keeps passing with `HOME="$CFG"`.

- [ ] **Step 2: Run; expect the new cases to FAIL.** `./tests/run.sh reconcile-agents` (the suite needs the sandbox off; its `test-requires` line says so)

- [ ] **Step 3: Implement.** `parse_manifest` accepts `claude_mcp` into a deduplicated `claude_mcps`, rejecting a value outside `^[A-Za-z0-9._-]+$` or starting with `.` (warn, `status=1`). `reconcile_claude_mcp`, per name: `cmd="$HOME/.local/bin/$name"`; warn if `[ ! -x "$cmd" ]`; desired JSON from `jq -nc --arg c "$cmd" '{type:"stdio",command:$c,args:[],env:{}}'`; read `$HOME/.claude.json` (missing → treat as no servers; unparseable → warn naming the file, `status=1`, skip all). An entry matches when `(.type // "stdio") == "stdio" and .command == $c and (.args // []) == [] and (.env // {}) == {}`. Absent → `claude mcp add-json "$name" "$json" --scope user`; match → `log_info "claude mcp present: $name"`; differs → `log_info "claude mcp replace: $name"`, `claude mcp remove "$name" --scope user`, and only if that succeeds, add. Every failure warns and sets `status=1`. Never print an entry's content. Header comment: MCP servers are replaced on drift, unlike plugins, because the declaration is the whole definition and a hand-made entry is what carries the token.

- [ ] **Step 4: Declare it.** `plugins.conf`: add `claude_mcp` to the Kinds comment with one line on the launcher naming rule, then `claude_mcp          ha-mcp` after the `claude_plugin` block.

- [ ] **Step 5: Run; expect all PASS.** `./tests/run.sh reconcile-agents`
